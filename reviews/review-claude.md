- **Phase 1 的「ensemble 與單一模型比較」**：`PLAN.md` §1.2 Q1 與 §4.3 已規劃同樣的比較；草案補上「比較後要做什麼決定」這一步，是有用的補充。

#### 2. 不同意的部分（每點附理由）

1. **Phase 0 排名第一的熱點其實已經知道，而且不是 Phase 2 要處理的「研究品質」問題。**
   D116 的歷史重播中，MiniBench 固定分母 60 題只有 38 題是已支援題型（是非、多選），雙場 104 題中支援 67 題，也就是約 **36% 的題目是數值／離散等目前不作答的題型**。支援題的準時覆蓋率已達 97.37%，但全部題目只有 61.67%。依草案自己的 Amdahl 原則，最大的分數上限在 `PLAN.md` M5（數值題與離散題），不在結算來源對應層：沒作答的題目是 0 分，而研究品質的改進只能在已作答題目上邊際增加分數。

2. **「比較三模型 ensemble 與單一模型的 peer score」無法直接做。**
   只有整合結果會送出，所以官方 peer score 只存在於整合預測；單一模型只能用本地的 log score 做反事實比較（`PLAN.md` §4.3 已這樣設計）。另外，三家額度是三個獨立帳號的訂閱，**停掉一條線並不會讓其他線多出額度**；簡化架構省下的只有維護時間，不是算力。因此「差距不大就簡化」的收益比草案假設的小，而三線整合在對數計分下通常能降低極端錯誤。若要採用這條決策規則，應該照 `PLAN.md` §4.3 的結論紀律（100 題以上、信賴區間不涵蓋 0）才下結論。

3. **核心原則 2「訂閱蓋工廠，API 當燃料」與現行決策衝突，而且前提不成立。**
   D35 已決定本版只用訂閱方案的官方 CLI；硬性規則 4 與 §7 的隔離設計都建立在這個前提上。主辦方的 LLM 額度需要申請、經挑選，不是保證取得。改走 API 也不只是換呼叫方式：API 模型沒有 CLI 內建的網頁搜尋，需要另外接搜尋工具（例如 V19 的 AskNews），預算、額度驗證、基準比對與驗收都要重做。這可以當作下一季的候選方案，但不應該寫成本計畫的原則。

4. **Phase 1「本季當熱身，正式目標放在下一季」值得重新評估。**
   排名依總分，晚加入的代價是題數較少，而不是被扣分；主賽獎金池是 MiniBench 的 50 倍。`PLAN.md` M6 目前也寫「主要目標是下一季」，但這是 D49（數值題排在主賽之前）連帶的結果。若 M4 第一輪健康，可以評估讓主賽的是非／多選題先上線，數值題之後再補。這需要 Louis 決定，也要先跑雙場覆蓋率重播（D116 雙場修題情境的 Mini 子集只有 89.47%，未達 90%）。

5. **Phase 3（Apify 販售）與 Phase 4（客製服務）不屬於本專案範圍，不建議放進 `forecast-lab`。**
   `PLAN.md` D31 的目標是最大化比賽分數。販售與接案會碰到本專案沒有處理過的條件：GPT 線使用女友的帳號，她只同意用於比賽（D35）；個人訂閱方案用於商業服務的條款風險，比 D35 已接受的比賽用途更高；草案提到的「Fall 2026 起商業 bot 不能領獎」本專案的規則摘要沒有記錄，賣出 bot 的模組是否會影響領獎資格，需要先查證原文。若要做，建議另開專案與 repo，不使用三條預測線的帳號。

6. **以預測市場交易者為目標客群需要特別小心。**
   賣資料工具本身不是下注，但硬性規則 1 禁止撰寫任何交易或下單程式；販售給交易者的工具很容易被要求加上下單或訊號功能。若日後真的做，須在範圍中明文排除。

#### 3. 本計畫遺漏的風險

1. **無人值守期間的「人為核准點」**：目前正式參賽是七天有限窗口、無自動續期（D117／D118）；基準比對發現全域設定變動時，該線會停住，等人工處理。今天就發生一次：Claude 線在首輪因 `~/.claude/plugins` 內容雜湊變動而暫停（見附錄）。12 月中旬無法介入時，這兩類核准點都會讓系統停擺。需要事先決定：窗口要預先核准多長、哪些環境變動可以自動歸為資訊性、哪些必須停線。
2. **主機可用性**：D116 的 7.43 小時停機情境覆蓋率只有 73.68%。無人值守期間的停電、睡眠、網路中斷，目前只靠 TG 通知；需要一份出發前檢查清單（電源、睡眠設定、CLI 自動更新、登入狀態）。
3. **CLI 自動更新**：任何一家 CLI 自動更新都可能改變基準或行為。無人值守前應確認更新策略。
4. **Metaculus 使用條款**：題型普查若下載大量歷史題目全文並儲存，可能牴觸「禁止儲存大量內容」（`PLAN.md` §3.7）。普查應只保存衍生統計（題型、來源類別、計數），不保存全文。
5. **「不得先看開放中題目的輸出再修改機器人」**：普查與 Phase 2 的分析只能使用已關閉、已結算的題目，以及本專案已關閉題目的輸出。
6. **女友帳號的同意範圍**：任何超出比賽用途的使用都需要她重新同意。
