## M2-W1 交付物

- `src/aggregate.py`：從追加順序的嘗試歷史固定每線每層第一個 valid；後來確認污染或快照不符時排除，不改挑後面的答案。final 優先採合格第 2 層，否則使用同線合格第 1 層。保留缺線、排除原因、attempt ID、快照映射、規則版本與設定 hash。
- `agg_v1`：是非題等權 log-odds 平均，最後才裁切 [0.02, 0.98]；多選題 log-space 幾何平均、正規化後以 ε=0.02 均勻平滑。沒有有效答案則 `no_valid_inputs`，不捏造機率。
- `effective_flags`：結合既有標記與事後追加稽核，沿 `prev_attempt_id`、`input_attempt_ids` 傳播。模型不符、違規工具、確認洩漏與缺少／不相容依賴皆排除；suspected 標記保留但照常使用。重複 ID、循環及指向未知嘗試的稽核事件直接拒絕。此處僅計算傳播，尚不寫入歷史整合／送出影響清單。
- `src/escalate.py`：依 `run_config_v2` 計算升級候選。是非題先裁切各線才比較 log-odds；多選題依 D53 使用驗證前原機率；exact 市場需可解析的時間、合法機率、完整的同名選項對應。0／1 市場價格以 0.005／0.995 代入，原值保留。模型標記 `resolution_ambiguity`、`evidence_conflict` 也觸發候選。
- `evaluate` 回傳含 `escalation` 的整合紀錄，列出所有觸發條件、強度與被排除市場的原因；候選仍為 `pending_budget_and_deadline`，不直接啟動第 2 層。
- `append_local_aggregate` 只在呼叫者明確指定的路徑追加 local 紀錄。沒有 CLI 自動抓帳冊、沒有外部服務呼叫，也未接入 `forecast.py`。

實作版本：整合初版 `aggregate_pipeline_v1`，M2-W2 因稽核來源追蹤升為 `aggregate_pipeline_v2`；升級判斷仍為 `escalation_v1`。沿用已定稿的 `agg_v1`、`run_config_v2`，未改權重、門檻或模型。遇到其他設定直接拒絕，避免在相同版本名下默默套用未知規則。

## 測試與限制

`tests/test_aggregate.py` 共 42 個案例：數學預期值、排列不變性、裁切時點、多選總和與下限、缺線與無答案、第一次採用不可換選、final 分層回退、快照與 ID 映射、晚到污染跨線傳播、工具／模型異常、缺依賴與循環、非有限值、完整市場對應、原始多選分歧、候選不等於准入，以及 JSONL 追加。

模型宣稱市場 `match=exact` 且選項同名，仍不是程式獨立證明結算條件同義；本模組只檢查可機器判斷的必要條件。事後影響帳冊與有准入門檻的第 2 層 local API 已由 W2／W3 實作；W4 本地排程／預算與 W5 留言現已實作；W6 只有名單、量測工具與部分隔離驗收，真實 20 題尚未執行，不應宣稱 M2 已完成。

## 哪些事情需要 Claude

- **需要 Claude Code 額度的工作**：現有 `claude` CLI 路徑的正式模型驗收與預測實測。可由任何獲授權的協調者操作，不必由 Claude 當開發協調者。
- **不限定 Claude 的工作**：寫程式、離線測試、文件維護，以及由未參與修改者進行的獨立複審。使用者提出的 agy／Opus 5.5 可先作開發與審查替代路徑。
- **需要 Louis 的工作**：全域基準人工核准與 trial／live 模式核准；不能由任何模型自行代替。
- **agy／Opus 與預測線的差別**：同一模型經另一個 CLI 執行會改變工具、設定、額度歸屬與可觀測資訊。開發審查可使用它，但不能把這次審查呼叫視為原 `claude` 預測線已驗收，也不自動改寫正式預測配置。
