## 目標

新增 `src/submit.py`，把整合後的最終結果與 `comment_v1` 的留言，依 §3.6 的送出契約與狀態機送出。這個工作只做離線實作與測試：

- 實際會寫入 Metaculus 的請求，經由可替換的傳輸層（`Transport`）發出；測試一律使用假的傳輸層，不連網。
- `local` 模式下，`submit.py` 不建立任何寫入請求，只產生「本來會送出什麼」的本地紀錄（`dry_run`），供檢查。
- `trial` 與 `live` 模式的真實傳輸層可以實作，但只有在下列全部成立時才可能被使用：`config/submit_mode.json` 為 `trial` 或 `live`、`config/STOP_SUBMIT` 不存在、目標場地在該模式允許的清單中、執行前重查全部通過。程式中不得存在繞過這些檢查的路徑。不要執行任何會連網的指令。

## 規格

1. **輸入**：題目快照、`scheduler.py` 產生的最終整合紀錄（只接受 `submission_eligible = true` 的紀錄）、`comment.py` 組成的留言與其 hash。送出目標（`tournament_id`、post ID、question ID、選項識別、快照 ID）只能取自抓題資料的對應，不得取自模型輸出的文字或網址。
2. **執行前重查**（任一不符就記為 `rejected_precheck` 並保存原因，不送出）：
   - 帳號身分等於核准的機器人 ID（由設定提供；trial 前不存在時一律拒絕）；
   - 題目屬於該模式允許的場地、仍在開放中；試驗場地的題目不是比賽的同步題（沿用 `poll_questions.is_synced_copy`）；
   - 截止時間、題型與選項與快照相符，而且還沒超過本地的送出截止時間；
   - 機率在範圍內，並與本地整合結果一致；
   - 本帳號在該題還沒有預測：「機器人 ID + question ID」跨比賽去重，同時檢查本地紀錄與平台回傳的既有預測。平台欄位的確切名稱屬 V15，請把讀取邏輯集中在一個函式，並在任務回報中列出假設的欄位。
3. **多選題總和修正**：前 K−1 個選項四捨五入到小數點後 6 位，最後一個取 1 減去其餘的總和；確認每個選項都在平台允許的範圍內（範圍值放在設定或常數中，標示待 V15 確認）。
4. **狀態機**（每一步都追加寫入 `data/submissions.jsonl`，不覆寫）：
   - `intent`：題目對應、整合紀錄 ID、要送出的機率、留言 hash；
   - 送出預測（以 question ID）→ `forecast_ok`（保存回應與遠端 ID）；
   - 送出留言（以 post ID；`is_private = true`、`included_forecast = true`）→ `comment_ok`；
   - 逾時或連線中斷 → `unknown`：重建意圖後，預測與留言分別以讀回對帳；暫時查無資料不能當作沒有受理，無法確認時維持 `unknown`，並停止該筆的後續寫入；只有確認沒有成功才以原內容重試；
   - 預測成功、留言確認失敗 → 只重送同一份留言，以指數退避重試；仍失敗就標記 `comment_failed` 並記錄須通知 Louis。不重新執行模型，也不重送預測；
   - 每次寫入前都重新檢查送出模式、場地清單與 `config/STOP_SUBMIT`；停用後，尚未開始的請求不再送出，已送出的只能對帳。
5. **每題只送一次**（D44）：白名單比賽的題目，同一個 question ID 只會有一筆成功的預測與一則留言；重啟後依 `submissions.jsonl` 接續，不重複送出。試驗場地允許重送，但流程相同；請把「是否允許重送」做成依場地決定的明確參數，預設不允許。
6. **鎖與中斷**：與 `scheduler.py` 使用一致的鎖，避免兩個程序同時送出同一題；中斷後的接續以帳冊為準。
7. **CLI**：`python src/submit.py run`（依目前的送出模式處理所有待送出的最終結果；`local` 只寫 `dry_run` 紀錄）與 `python src/submit.py reconcile`（只對帳，不送新的請求）。

## 驗收條件

- 單元測試涵蓋 §10 M3 第三項列出的每一種情形：ID 對錯題、錯帳號、跨比賽重複、選項修訂、同步題與已關閉題目都被拒絕；平台已有預測時不再送出；預測與留言各自「伺服器已受理但回執遺失」、讀回失敗或延遲可見、重啟之後都能正確對帳；留言失敗時只補送留言；停用開關（`local` 模式與 `STOP_SUBMIT`）有效；`local` 模式下假傳輸層收不到任何寫入請求。
- 多選題總和修正的邊界情形；送出目標不受模型輸出影響的測試。
- 完整測試 `.venv/bin/python -m pytest -q` 全部通過。
- 不修改 `config/submit_mode.json`、`config/tournaments.json` 與任何送出白名單；不建立 `trial` 或 `live` 的設定。
