### 3. 對 `PLAN.md` §7.3 與 §7.7 的修正建議

1. **[§7.3] 移除 `use_ai_credits` 候選鍵，固定只傳 `"useG1Credits": false`**：
   - `agy 1.4.12` 對 `--settings` 有嚴格 schema 檢查，傳入未知鍵 `"use_ai_credits"` 會直接報 `Error: --settings: unknown setting "use_ai_credits"`（exit 1）；而 `"useG1Credits": false` 可正常通過並在 `/config` 的 `command.data.config.useG1Credits` 顯示為 `false`。建議將 §7.3 與 §7.7 中提及雙鍵候選的描述改為固定單鍵 `"useG1Credits": false`。
2. **[§7.3、§7.5] 明確區分 `agy` 兩種工具拒絕的行為與證據來源**：
   - **Ask 規則在無互動模式（`-p`）下的自動拒絕**（如 `agy_r4a.json`／`agy_r4a.log`）：`agy` 會在 log 記錄 `Print mode: soft-denying tool confirmation "<ToolName>" at step <N>` 並立即中止當輪，JSON 外框的 `status` 仍為 `"SUCCESS"`、`response` 為空字串 `""`，且外框帶有 `"denied_actions": [{"action": "...", "display_name": "..."}]`。此時因回覆為空，`completed = False`，應判為 `error_type = "tool_denied"`。
   - **Deny 規則（`permissions.deny`）的硬性拒絕**（如 `cmd_denied.json`／`cmd_denied.log`）：工具呼叫在 CLI 內直接回傳 `Matches user-configured deny rule` 給模型，不會中止當輪，模型會繼續完成結構化輸出（`status == "SUCCESS"` 且 `response` 非空），JSON 外框**不會**出現 `denied_actions`，`agy_cli.log` 也不會印出 `soft-denying` 行。證據須從模型輸出（`response`／`structured_output` 中的 `Matches user-configured deny rule` 與拒絕項目）擷取，並以 `source = "model_output_deny_rule"`（標註 `evidence_strength = "model_self_report"`，與 CLI 層可驗證之 `"cli_verified"` 區分）併入 `denied_actions`。
3. **[§7.7] 額度桶群組聯動與並行污染判斷**：
   - Flash／Pro 屬於同一個 `"Gemini Models"` 群組，單次執行會同時扣減 `gemini-weekly` 與 `gemini-5h` 兩個桶；判斷時將 `("gemini-weekly", "gemini-5h")` 視為同一模型家族群組（已獲協調者裁決確認）。只有當不同模型家族群組（例如 Argon、Flash/Pro、`3p` 中任兩組）同時變化、任何桶上升或重置、出現不認得的桶、缺少判斷所需的比較桶，或數值非有限 `0～1` 比例時，才判為 `undetermined` 或 `unverified`。

### 4. `gemini-3.8-flash-low` 沒有開網頁的線索分析與推測原因

從 `review_inputs/agy/tier1.json` 與 `review_inputs/agy/tier1.log` 比對 `agy_r4a.log`，可整理出三項待本機實測驗證的推測與線索：

1. **待驗證推測一：模型可能僅執行搜尋而未發出讀網頁的工具呼叫**：
   - `tier1.log` 第 194～197 行共有 3 次 `streamGenerateContent` 與 1 次第 196 行的非串流 `v1internal:generateContent`（推測可能對應後端搜尋或輔助呼叫，待實測確認），且整份 `tier1.log` 未出現 `Monitor agy_tool_safety FINISHED` 或 `tool_confirmation_manager.go` 的紀錄（對照 `agy_r4a.log` 第 186～212 行呼叫 `ReadFile` 時有出現）。惟一般 RPC 名稱與 safety log 缺席尚不足以單獨證明工具實際呼叫與否，仍待下方本機實測確認。
2. **待驗證推測二：預設 agent（`agent=false`）的工具宣告清單可能未包含 `read_url_content`**：
   - `tier1.log` 第 155 行顯示 `Starting new conversation (agent=false)`。在 `agy 1.4.12` 中，當未指定 `--agent` 時，CLI 使用預設 agent 的工具宣告；預設工具集包含 `search_web`，但網頁瀏覽在預設環境中可能依賴 `/browser` 子代理（而 `--disable-slash-commands` 已關閉 slash commands），預設宣告給模型的頂層工具未必包含 `read_url_content`。`--settings` 中的 `"allow": ["read_url(*)"]` 只設定權限引擎（當工具被呼叫時是否放行），**不會**把未宣告的工具加入模型的 tool declarations。因此模型在 `tier1.json` 回報：`"I located the official website for the Python Software Foundation via web search, but I do not have a browser tool available to directly open and view webpage contents."`。
3. **待驗證推測三：提示詞用詞（「open」）與 `gemini-3.8-flash-low` 的工具對應**：
   - 若預設 agent 實際上有宣告 `read_url_content`，則可能是測試 prompt 要求「open URLs」，而 `gemini-3.8-flash-low`（低推理強度）在工具清單中尋找 browser 類工具未果，便直接將兩個網址都放進 `refused`。

**給協調者的本機實測驗證建議**：
- 在 `tier1`／`acceptance` 同樣寫入一個最小自訂 agent（`excludeDefaultComponents: true`、`tools: ["search_web", "read_url_content"]`）並加上 `--agent` 重跑一次 `tier1` 測試：
  - 若加上 `--agent` 後 `gemini-3.8-flash-low` 就能正常呼叫 `read_url_content` 開啟 `python.org` 並擋下 `metaculus.com`，即證實是「預設 agent (`agent=false`) 未宣告 `read_url_content`」，屆時 `tier1` 與 `acceptance` 也應一併改用最小自訂 `--agent`（不含 `invoke_subagent`）。
  - 若加上 `--agent` 後仍不呼叫，可在 prompt 中明確指名使用 `read_url_content` 工具或改以 `gemini-4-argon-medium` 對照測試。
