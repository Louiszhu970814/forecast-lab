## 事前固定的觀測設計

審查通過後才登記絕對 UTC 起訖，起點須在登記之後。選定一次 **24 小時開題窗口，加 4 小時收尾**；後段只補觀測、接收已關閉題的 inventory，不增開題分母。不是固定試驗天數的新門檻，也不承諾一天就能取得足夠樣本。

- 場地：主賽 33121，加每次官方 MiniBench index 所列 ongoing、目前 alias，以及在本觀測期開始的輪次。第一次發現後持續列舉，即使中途結束或 alias 轉移也不移出。沒有重新挑題。
- 每 600 秒一個固定觀測槽；每槽最多 480 秒、80 次 GET，單一場地最多 20 頁、每頁 100 posts，最多 8 個 project，整次最多 8000 個 GET 嘗試。雙次列舉會增加請求；實際頁數尚待實機觀測，不宣稱此預算一定足夠。這是觀測器自己的格點，**不冒充預測 launchd**。
- 每次均列舉已公開、已核准範圍的 `open/upcoming/closed/resolved`，不限制題型。由回傳的 project membership 核對場地，保留群組與條件題的所有 child ID，只有獨立 binary／MC 計入支援題。Notebook 不屬預測題。凍結 `listing_order=published_at` 與 `inventory_passes=2`；每個場地連續完整列舉兩次，兩次 post ID 與 post/question/shape 對應集合必須一致，各頁若有 count 也須一致且等於實際列舉數。只有核對通過才追加快照，兩次的 metadata 都保留，第二次完成才可供重播取得。這是兩次列舉一致性檢查，仍不是伺服器原子快照；有任何不一致就停止本次觀測。完整場地與完整輪詢分開記錄。
- 分母規則：在任一完整快照中，`start <= open_time < cohort_end` 的所有 question ID 聯集；修訂把開題移出窗口也不刪掉已納入的題目。多場地同 ID 不重複計數。未支援、缺時間、不明型態、重複映射與取樣邊界須另列，不以已成功發現的支援題當作整個比賽母體。
- 逐次記錄實際輪詢起訖、GET 呼叫起訖、經節流後的網路開始、分頁完成、場地、題號、狀態、排定時間、內容與結構 hash、實際關閉時間、內容欄位可用性及逐頁完成。gateway 將正文在開放前／關閉後變成 null，不能將此 hash 變化直接當作內容修訂。首次可見只能限定在相鄰觀測之間；快照完成才當作已取得，不回填零延遲。
- 任何 HTTP 錯誤（含 4xx／429）、讀取失敗、異常結構、分頁超限、時間或請求超限均結束本次觀測，不自動補跑。共享 Retry-After 保留。睡眠造成的漏槽記為 missed，不密集補查。
- 登記凍結 policy 與程式 hash；已開始即不可重跑或續期，歷史只追加。無開題、缺漏、修訂無法界定、或期末仍未完整觀測就明列不足，另行事前登記新窗口，不能事後延長此窗口。

實際登記、開始與完成均以 `data/metadata_observations/<ID>/` 的 JSONL 為準。只有啟動過才可報告「觀測中」。程序以固定的 interpreter 執行，可用 `caffeinate -i` 保持運行；不安裝／修改任何 LaunchAgent。機器關機、蓋上螢幕或程序結束仍可能造成缺口。
