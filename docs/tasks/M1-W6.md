## 已確認的事實（協調者 2026-10-31 以 codex-cli 0.166.0 實測，樣本在工作目錄的 `review_inputs/codex/`）

- 以 PLAN §5.3 的完整停用清單（含 `shell_tool`、`unified_exec`、`view_image`）執行時，模型回答「沒有 shell 或列出檔案的工具」。
- 事件順序：`thread.started` → `turn.started` → `item.started` / `item.completed`（`web_search`、`agent_message`）→ `turn.completed`（含 `usage`）。
- 樣本中有兩個 `web_search` 項目：一個 `search`（34 筆結果，帶各自的網址與網域），一個 `open_page`（`www.python.org`）。
- **可觀測性限制的實例**：模型最後的答案聲稱「已開啟 https://www.metaculus.com/questions/」，但事件中沒有任何對 metaculus.com 的 `open_page`，搜尋結果也沒有。依 PLAN §3.3，模型自己回報的 `sources` 含 metaculus.com 時要判為 `leak_confirmed`；事件看不到的部分記為 `unknown`。這個樣本要做成測試案例。
- 前幾輪審查的事件樣本（`review_inputs/codex/gpt_r2.jsonl` 等）另外包含 `command_execution`、`file_change` 與 `find_in_page`，可以用來測試 parser 對各種項目的處理；預測時這些工具不應該出現。

## 交付物

- `src/adapters/gpt.py`：
  - `build_argv`：依 PLAN §5.3 組參數。
    - 停用清單逐項以 `--disable` 傳入；`tier2` 從清單中移除 `multi_agent`，並加上 `--enable multi_agent`，預設關閉。

    - prompt 由標準輸入傳入；`--output-last-message` 與 `--output-schema` 都使用 raw_dir 內的絕對路徑。
  - `parse`：
    - 讀事件 JSONL：同一個 item ID 的開始與完成事件合併，只計一次；無法解析的行要記錄，不能直接略過。
    - 最終答案取 `--output-last-message` 的檔案；JSON 解析失敗時，`structured` 設為 `None`。
    - `url_events`：`open_page` 的 `action.url` 記為 `opened`（CLI 沒有回報失敗時）；`search` 結果的網址記為 `unknown`，`source` 標為 `search_result`；`find_in_page` 沒有動作網址，依結果網址記為 `unknown`。
    - 依 PLAN §5.5 的表格對應 token 欄位；多次 `turn.completed` 時各自保存，不自行加總。
    - `tool_call_counts`：依項目類型計算可觀測的事件數，並在欄位說明中註明「不等於查詢數或實際開頁數」。
    - 出現 `command_execution`、`file_change` 等不應存在的工具項目時，記錄在 `denied_actions` 之外的違規清單，並讓結果標為需要稽核。
    - `reported_model_id` 為 `None`，`model_check` 為 `unverified`（PLAN §7.7）。
    - 判斷 `completed`：有 `turn.completed`，沒有 `turn.failed` 或 `error` 事件，最終答案檔存在且不是空的。
  - `cli_version`：解析 `codex --version`。
- `tests/test_adapter_gpt.py` 與 `tests/fixtures/gpt/`：從 `review_inputs/codex/` 的樣本製作精簡版 fixtures，長文字改短，不保留審查內容。
