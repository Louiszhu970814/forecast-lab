- 執行：GPT（代理開發模式，D56）
- 審查：Claude
- 依賴：W2＋W3（`baseline.py`、`acceptance.py`、adapters）
- 需要閱讀的 PLAN 章節：§7.2（全域基準、變更處理）、§7.6 第 7 項與判定標準、§5.3（三條線的指令骨架）

## 為什麼需要

`baseline.approve()` 要求先有一筆 `type = "autoload_result"`、`passed = true` 的紀錄，但目前沒有任何程式產生它。這是 M1 與 M2 都無法收尾的原因：沒有核准的全域基準，執行前檢查就不放行（`forecast.py`、`scheduler.py` 都沒有 waiver）。

## 目標

新增 `src/autoload.py`：在各 CLI 會自動載入的全域位置暫時放入含 canary 的假內容，以正式設定執行各線，核對 canary 是否出現、以及 CLI 實際宣告載入了哪些來源，最後把所有檔案還原成原狀並逐一驗證，寫入一筆 `autoload_result`。

這個工具會暫時修改 Louis 的全域檔案，所以：

- 只能由人在場時執行（人工驗收），不得被排程、`acceptance.py` 或任何自動流程呼叫；
- 必須帶 `--approved-by <名字>` 與 `--i-understand-this-edits-global-files` 兩個參數才會動手；沒有這兩個參數時只做 `plan`（列出會放哪些檔案、會備份哪些檔案），不修改任何東西；
- 單元測試一律使用暫存的假 HOME 與假 adapter，絕不觸碰真實的家目錄。

## 規格

1. **測試位置**（每線各自一組；路徑以 `baseline.default_sources()` 與 `ancestor_sources()` 的盤點為準，至少包含）：
   - claude：`~/.claude/CLAUDE.md`、`~/.claude/skills/flab-autoload-<tag>/SKILL.md`；
   - codex：`~/.codex/AGENTS.md`、`~/.codex/skills/flab-autoload-<tag>/SKILL.md`；
   - agy：`~/.gemini/GEMINI.md`、`~/.gemini/AGENTS.md`、`~/.gemini/config/rules/flab-autoload-<tag>.md`、`~/.gemini/config/skills/flab-autoload-<tag>/SKILL.md`；
   - 共同：暫存資料夾的上層目錄（`flab-runs` 的父目錄）中的 `AGENTS.md`、`CLAUDE.md`、`GEMINI.md`、`.agents/rules/flab-autoload-<tag>.md`。
   每個位置的 canary 不同（例如 `FLABAUTO-<tag>-<序號>`），以便知道是哪一個來源被載入。
2. **備份與放置**：
   - 動手前記錄每個目標的狀態（不存在／一般檔案的 sha256 與內容複本／其他類型）。目標是 symlink、目錄、或不是一般檔案時，整個測試拒絕執行。
   - 已存在的檔案：在檔尾追加一段含 canary 的文字；不存在的檔案：新建（必要時建立其上層資料夾，並記錄建立了哪些資料夾）。
   - 備份放在 `data/autoload_backups/<run_id>/`（`data/` 不進版本控制）。
3. **執行**：每條線以正式的第 1 層模型與推理強度、與預測相同的 adapter 與隔離設定執行一次（不另開權限）。prompt 請模型列出它看得到的任何以 `FLABAUTO-` 開頭的字串，沒有就回答 `NONE`；不要求它讀檔。另以 `--cheap` 允許使用 `acceptance` 區塊的便宜模型做開發試跑，但這種結果記為 `passed = false`、`mode = "cheap_dry_run"`，不能用於核准。
4. **判定**（D43：不能只因輸出中沒有 canary 就推論沒有載入）：
   - 每個位置分類為：`loaded`（canary 出現在模型輸出或原始輸出中，或出現在 CLI 宣告的載入來源中）、`not_loaded`（canary 沒有出現，而且 CLI 的宣告可以證明該來源沒有載入）、`unknown`（canary 沒有出現，但沒有宣告可以佐證）。
   - CLI 宣告的來源：claude 取 stream-json 的 init 事件（skills、plugins、mcp_servers 等）；codex 取 `codex debug prompt-input`（在與執行相同的設定下）中出現的指示與 skills；agy 若無可用宣告，就只能是 `loaded` 或 `unknown`。
   - `passed = true` 的條件：三條線都執行完成、所有檔案都還原並驗證成功、沒有執行錯誤。`loaded` 與 `unknown` 都不算失敗，兩者都列入 `must_review`（§7.6：無法避免載入的來源記為「會載入」，納入基準審查）；`unknown` 依 D43 保守視為「可能載入」，在 `must_review` 中標明 `outcome = "unknown"`。只有 `not_loaded` 可以不列入。
   - （2026-11-01 審查修訂，協調者 Claude：原條件要求沒有任何 `unknown`。agy 沒有來源宣告，該條件實際上無法達成；改為保守地把 `unknown` 視為會載入、交給人工審查，不由沒有出現 canary 推論沒有載入，仍符合 D43。）
5. **還原**（在 `finally` 中執行，任何例外或中斷都要還原）：
   - 原本存在的檔案還原為備份內容，並驗證 sha256 與動手前相同；新建的檔案與新建的資料夾刪除，並驗證已不存在；
   - 任何一項驗證失敗：紀錄 `restore_ok = false`、列出未還原的路徑與備份位置、以非零結束碼結束，並印出明確的人工還原指示。
6. **紀錄**：追加到 `data/acceptance.jsonl` 一筆 `{"type": "autoload_result", "record_id", "run_id", "mode", "approved_by", "models", "cli_versions", "locations": [{player, path, kind, canary_sha256, outcome, evidence}], "must_review", "restore_ok", "passed", "started_at", "finished_at", "raw_dir"}`。紀錄中不寫入 canary 原文以外的使用者檔案內容。原始輸出放在 `data/autoload_runs/<run_id>/`。
7. **CLI**：`python src/autoload.py plan`、`python src/autoload.py run --approved-by Louis --i-understand-this-edits-global-files [--players claude,gemini,gpt] [--cheap]`。

## 驗收條件

- 單元測試（假 HOME、假 adapter、假 CLI 宣告）涵蓋：plan 不修改任何檔案；缺少任一確認參數時拒絕；symlink 或目錄目標時拒絕；已存在檔案的追加與還原後 sha256 相同；新建檔案與資料夾的刪除；執行中丟出例外時仍還原；還原驗證失敗時的結束碼與紀錄；`loaded`／`not_loaded`／`unknown` 的分類；`--cheap` 永遠不是 `passed`；`baseline.approve()` 接受這筆紀錄。
- 完整測試 `.venv/bin/python -m pytest -q` 全部通過。
- 不得執行 `autoload.py run`，也不得以任何方式修改真實家目錄下的檔案。

### 與規格不同之處及理由

- `--players` 選取部分線時仍可測試、保存結果，但 `passed` 固定為 false。理由：現有 `baseline.approve()` 只看通過旗標，不能讓單線結果核准未測試的其他線。
- Codex 探測沿用 acceptance 的無使用者設定 mirror，使用同一工作目錄、模型目錄檔及 adapter 參數覆寫。既有程式記載 debug 指令不支援 exec 的 `--ignore-user-config`／`--strict-config`，因此不能宣稱設定完全等價：找到 canary 或來源可列為 loaded，缺少來源只列 unknown，不用 mirror 的沉默證明 not_loaded。Claude 的完整、可辨識 skills 清單只能排除 skill，不能排除其他指示來源；agy 沒有可用來源宣告時維持 loaded／unknown。
- 除規格列出的特殊目標外，也拒絕硬連結檔案與路徑中含 symlink／非目錄的父層，避免追加或還原影響別處。
- 額外要求 CLI 版本已知、adapter 完成且無錯誤，才算該線執行完成；任一執行例外會中止後續線並先還原，不自動重跑。這些情況均不能核准。
- 不可攔截的 SIGKILL、斷電無法執行 Python finally；保留已 fsync 的備份及追加式 manifest 作人工復原依據。可攔截的中斷有離線測試；復原期間忽略重複中斷，避免再次打斷復原。若儲存裝置本身無法寫入，不能保證新增 acceptance 紀錄，但復原失敗指示會在寫結果日誌前印出。

### 做出的假設與限制

- 本項只向規格所列的惰性指示／rule／skill 位置放測試內容，不改 settings、hooks、MCP 或管理者設定；其他全域內容仍由既有 baseline 盤點與人工審查處理。
- 人工執行期間不應同時修改這些目標，也不應並行啟動另一個 autoload 測試。只有兩項明確確認才能修改；程式沒有用 TTY 狀態推測是否有人在場。
