# M3-W2：持續輪詢、題目修訂與排程包裝

- 執行：GPT（代理開發模式，D56）
- 審查：Claude
- 依賴：M2-W4（`scheduler.py`、`budget.py`）、W7（`poll_questions.py`）、M3-W1（`submit.py`，並行開發中；本工作只需呼叫它的 CLI 介面，不修改它）
- 需要閱讀的 PLAN 章節：§3.2（含題目修訂）、§3.4、§3.5、§3.6（送出模式與停用開關）、§5.1、§7.2（每次執行前比對 CLI 版本與全域基準）、§9（全文）

## 目標

M2 的 `scheduler.py` 只處理預先固定的題集（campaign）。M3 需要無人值守地持續運作：每 10 分鐘查詢新題、處理題目修訂、把工作排進佇列、執行，再交給 `submit.py`。本工作提供這個「一個週期」的入口與 macOS 的排程包裝，但**不安裝**任何排程：安裝由 Louis 在核准 `trial` 後手動進行。

## 規格

1. **`src/cycle.py`**：執行一個週期後結束，供 launchd 每 10 分鐘呼叫一次。
   - 先取得全域鎖；上一個週期還在執行就直接結束並記錄（不排隊、不等待）。
   - 依序：檢查停用開關（`config/STOP_SUBMIT` 只影響送出；`players_enabled` 影響各線）→ 輪詢允許的場地（沿用 `poll_questions.py` 的函式，不另寫一套 API 呼叫）→ 依新快照更新工作佇列 → 在本週期的時間上限內執行排程器 → 呼叫 `submit.py run`。
   - 執行前檢查沿用既有的 preflight（CLI 版本、全域基準、驗收、額度）；任一線不通過就只停那一線，並記錄原因。
   - 每個週期追加一筆紀錄到 `data/cycles.jsonl`：開始與結束時間、每一步的結果、新題與修訂題的 ID、各線狀態、錯誤。
2. **持續題集**：把 M2 固定題集的機制延伸為「依輪詢結果持續加入新題」的模式。現有固定題集的行為與測試必須保持不變；新模式的預算窗口與上限沿用 `budget.py`，不得自行放寬保留線或上限。
3. **題目修訂**（§3.2、D53）：已抓到但尚未送出的題目出現新快照時：
   - 結算條件、標題或選項有實質變更：舊快照尚未採用的結果作廢；截止時間允許時，以新快照重新排入第 1 層；
   - 來不及重跑時：題型、選項或截止時間改變 → 不送出；只有文字修訂 → 允許送出舊快照的結果，但紀錄要標記修訂、維持綁定舊快照；
   - 已送出的題目再變更：只記錄，不重新送出。
   - 作廢與重新排入都要以追加紀錄表示，不改寫舊紀錄。
4. **launchd 包裝**（放在 `launchd/`，不安裝）：
   - 每 10 分鐘執行一次的 plist 範本，以 `caffeinate -i` 包住包裝腳本；另提供每天 21:00（台北時間）抓取結算與每週一 21:00 產生報告的 plist 範本（目標程式還不存在的，範本中保留並註明待 M3 後續工作）。
   - 包裝腳本設定工作目錄、使用 `.venv` 的 Python、把 stdout／stderr 寫到 `data/logs/`，不在命令列或 plist 中放入任何機密。
   - `launchd/README.md` 說明 Louis 如何安裝、檢查與移除；註明安裝前須完成的核准。
5. **時間上限**：一個週期的執行時間不得超過下一個週期的開始時間減去安全餘裕；超過時停止接新工作，等待中的工作留到下一個週期，並遵守 §3.5 的決策截止點。

## 驗收條件

- 單元測試（假的 API 回應、假 adapter、假時鐘）涵蓋：上一個週期仍在執行時直接結束；新題加入佇列；三種修訂情形的處理與「已送出後再修訂只記錄」；停用開關與單線停用；preflight 不通過只停該線；週期時間上限；`cycles.jsonl` 的紀錄；M2 固定題集的既有測試全部仍通過。
- 完整測試 `.venv/bin/python -m pytest -q` 全部通過。
- 不安裝、不載入任何 launchd 工作；不修改 `config/submit_mode.json`、`config/tournaments.json` 與送出白名單；不修改 `src/submit.py`。
