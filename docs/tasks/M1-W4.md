## 已確認的事實（協調者 2026-10-31 以 claude 2.1.316 實測，樣本在工作目錄的 `review_inputs/claude/`）

- 無互動模式下，`--tools` 只決定「有哪些工具可用」，沒有 `--allowedTools` 時，WebSearch 與 WebFetch 都會被權限檢查擋下（`system:permission_denied`）。所以必須同時傳 `--allowedTools "WebSearch,WebFetch"`。
- 封鎖 metaculus.com 需要兩條規則：`WebFetch(domain:metaculus.com)` 只擋主網域，`WebFetch(domain:*.metaculus.com)` 只擋子網域。兩條都加上時，即使有 `--allowedTools "WebFetch"`，拒絕仍然優先（V9）。
- `--restricted` 會忽略 user、project、local 的設定檔，並在 `--tools` 沒有列出時移除會執行程式碼的工具與 WebFetch。它可能就是 V3 的答案，請在參數中加入，並在測試中記錄理由。
- `--output-format stream-json --verbose` 的事件包含：
  - `assistant` 訊息中的 `tool_use`（WebSearch 的 `query`、WebFetch 的 `url`）；
  - `user` 訊息中的 `tool_result`（`is_error`）；
  - `system` / `permission_denied`（含 `tool_use_id` 與 `message`）；
  - 最後的 `result`，含 `usage`、`modelUsage`（鍵就是實際使用的模型 ID，例如 `claude-haiku-5-5`）、`permission_denials`、`structured_output`、`total_cost_usd`、`num_turns`、`is_error`、`subtype`。
- `--output-format json` 只有最後的 `result` 物件，看不到逐次的工具事件。為了稽核網址（PLAN §3.3），改用 `stream-json --verbose`。這是對 PLAN §5.3 骨架的修正，請在「執行回報」中註明。
- 樣本中，被 CLI 拒絕的請求不會出現在 `usage.server_tool_use` 的計數中，那裡兩項都是 0；工具次數請以事件計算。

## 交付物

- `src/adapters/claude.py`：
  - `build_argv`：依 profile 組參數。`tier1` 與 `acceptance` 使用：
    `claude -p --model <m> --effort <e> --tools "WebSearch,WebFetch" --allowedTools "WebSearch,WebFetch" --disallowedTools "WebFetch(domain:metaculus.com)" "WebFetch(domain:*.metaculus.com)" --restricted --strict-mcp-config --disable-slash-commands --no-session-persistence --output-format stream-json --verbose --json-schema <schema JSON>`
    - `format_repair`：`--tools ""`，不給任何工具。
    - `tier2`：子代理工具的名稱與限制，先以參數保留，預設關閉，於 W3 驗收時確認。
  - `parse`：
    - 從事件整理 `url_events`：`tool_use` 記為 `attempted`；有 `permission_denied` 的記為 `blocked`；`tool_result` 不是錯誤的 WebFetch 記為 `opened`；其餘記為 `unknown`。
    - 整理 `denied_actions`（取自 `permission_denials`）。
    - 對應 token 欄位：`input_tokens`、`output_tokens`、`output_tokens_details.thinking_tokens` → `reasoning_tokens`、`cache_read_input_tokens` → `cached_tokens`；`cache_creation_input_tokens` 只留在原始物件。
    - `reported_model_id` 取 `modelUsage` 的鍵；若有多個鍵（例如子代理用了別的模型），依主要模型判斷，其餘記錄在原始物件中。
    - 判斷 `completed`：有 `result` 事件，`subtype` 為 `success`，而且 `is_error` 為 false。
  - `cli_version`：解析 `claude --version`。
- `tests/test_adapter_claude.py` 與 `tests/fixtures/claude/`：以 `review_inputs/claude/` 的樣本製作精簡版 fixtures（保留事件結構，長文字改短），測試參數組成、網址狀態、拒絕紀錄、token 對應、模型 ID 與完成判斷。
