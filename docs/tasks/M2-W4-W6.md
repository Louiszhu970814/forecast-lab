## W4：有界本地排程

- `scheduler_v1`：跨題佇列，三線併行、同線最多一個 CLI。先完成所有可執行首層，再做升級候選；同級 EDF，記錄 MiniBench 近截止的例外。每完成一個工作重新查詢平台。
- `budget_v1`：campaign 先固定題集、設定 hash、七天窗口及逐線明確上限。預設準備器的 bootstrap 上限為每線 64 次，包含同窗口既有嘗試、兩層、重試、修復與驗收；它不是已量測的帳號容量，也不修改正式 `quota_policy.json` 的待定值。固定題集的預期新題為 0，另保留 2 次修復容量，之後才准入第二層。
- 每次 CLI 呼叫都有獨立 reservation、start、outcome；沒有 start 的舊 reservation 可釋放，有 start 沒結果則停線。首層明確容量不足記為 `budget_skipped`，額度不明仍暫停。被拒的第二層是終止決策，不能重啟後反覆排入。
- 首層 token 基準、同線同層 p90 耗時／Argon 消耗、每題第二層 token 與 Argon 上限、整週熔斷均留紀錄。缺成本／重置資訊時不假設可用。驗收中斷的呼叫也計入上限；舊驗收沒有逐次 journal 時保守算 3 次。
- `forecast_pipeline_v4`、`reconciliation_pipeline_v2`：改為逐線執行鎖與短時間共用 ledger transaction，使三線可併行，稽核／forecast 與額度讀寫保持一致。外部 CLI 執行期間不占整個 ledger 鎖。Gemini 的預設 preflight 實際查詢 credits，不再把未查詢的 `None` 當成當前餘額。
- scheduler 自己決定全題完成／截止，追加 `complete_local` 整合及留言。W3 的 provisional aggregate 不能拿來當完成。所有輸出仍 `submission_eligible=false`，沒有送出 API 或 launchd 安裝。
- 固定題集是 M2 量測用途；持續納入新題、送出前修訂重跑與 14 天無人值守驗收仍屬 M3。M2 遇題目修訂會阻止舊輸入新呼叫並保留失敗／缺答，不能以換題或挑答案提高有效率。

超過 3,000 字元依序移除來源、市場與細節，最後只縮減各線理由的完整句子／單字片段並標示省略。必要欄位仍放不下則拒絕產生，不硬切尾端。整合已寫入但留言尚未寫入時，中斷接續只補產生留言；不再呼叫模型。晚到稽核使原整合失效時，報表不把舊留言當成仍可採用。
