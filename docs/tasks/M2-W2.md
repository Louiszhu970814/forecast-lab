# M2-W2：追加式稽核依賴與事後影響帳冊

規格依據：PLAN §3.3（D48、D53）、§5.5、§10 M2。實作者：Codex；獨立程式審查：透過官方 agy 呼叫的 Opus 5.5。這是離線模組，不是模型預測／送出流程的驗收。

## 交付物與用途

- `src/audit_ledger.py`，版本 `audit_ledger_v1`：完整依賴關係檢查、事後稽核傳播、追加式影響帳冊、供整合使用的即時計算標記，以及明確指定來源檔案的 CLI。
- `src/aggregate.py` 升為 `aggregate_pipeline_v2`：整合紀錄保存真正影響採用／排除結果的稽核 ID 與來源紀錄，不把別題或未採用嘗試的事件混進來。數學規則仍是原本的 `agg_v1`。
- `tests/test_audit_ledger.py`：43 個合成案例。加上既有整合測試，相關測試共 85 個。

當 A 線的疑似污染在事後確認時，程式沿依賴關係追加受影響的修復、重試、其他線第 2 層、子代理、整合及送出狀態紀錄。原本的機率、採用紀錄和送出回執都不修改，也不重選答案、補跑或補送。

## 來源資料契約

所有節點必須包含相同題目映射欄位：`question_id`、`question_snapshot_id`，以及有記錄時的 `post_id`、`tournament_id`。依賴的兩端必須相符。來源記錄使用完整保留歷史，不只傳最新一行。

| type | 節點 ID | 資料依賴 |
|---|---|---|
| `forecast_attempt` | `attempt_id` | `prev_attempt_id`、`input_attempt_ids`、`input_subagent_ids` |
| `subagent_result` | `subagent_id` | `input_attempt_ids`、`input_subagent_ids`；另須 `parent_attempt_id` 指明啟動者，以及 harness 記錄的布林值 `result_delivered` |
| `aggregate` | `record_id` | `input_attempt_ids`；ready 結果必須有輸入 |
| `submission` | 每一狀態行的 `record_id` | `aggregate_id`；可保存共同的 `submission_id` 與各行 `state` |

subagent 與 submission 是本輪供離線驗證及未來 writer 遵循的契約，目前沒有啟用子代理或寫送出 API。

資料依賴不得形成循環。父代理啟動子代理另形成保守的「可能暴露」關係：父代理被確認污染時也標記子代理；如果子代理結果進入父代理上下文，子代理的污染也會回到父代理，不以最終答案是否引用判斷。`result_delivered` 必須是由 harness 記錄的布林值，且與子代理 ID 是否出現在啟動者的 `input_subagent_ids` 完全一致，否則拒絕處理。這種暴露關係可能互相連結，使用只增加標記直到不再改變的方式計算，不將它錯當成資料依賴循環。未交付給父代理的子代理結果不會反向污染啟動者；較早的上游答案也不因消費者污染而被回寫。

`audit` 沿用現有 `audit.py` 格式；事後新增判讀使用 `audit_update`，包含唯一 `audit_event_id`、`audited_at`、`audit_flags`、`audit_reasons`，目標可用 `attempt_id` 或 `{kind, id}` 的 `target`。兩種目標同時給出時必須一致。標記只能追加，空標記或後來的 clean 判斷不能抹除先前確認的影響。

## 帳冊與重啟

輸出建議路徑為 `data/audit_impacts.jsonl`，包含三類追加紀錄：

- `dependency_registered`：節點身分與完整來源紀錄 hash。
- `audit_registered`：稽核事件 ID、目標與完整事件 hash。
- `audit_impact`：某一事件對某一節點的影響，含題目映射、旗標、理由、來源事件／目標紀錄 hash；送出節點另保留原本的狀態與 submission ID。

`audit_impact` 是單一來源事件的影響，不是最後一行覆蓋以前標記。`exclude_from_future_use` 表示後續不能再採用，並不撤銷已送出結果。`retain_with_flag` 表示標記仍保留；讀取完整狀態時必須取聯集，不能讓後到的 suspected 抹掉 leak_confirmed。

每行 ID 由版本、類型、來源事件與目標身分決定；寫入時持有獨立檔案鎖，每行 fsync。重跑會核對已存在紀錄並只補缺行；新增後續節點時，舊事件也會補傳播。程序中斷留下完整行前綴可接續；損壞或缺少結尾換行的資料停止處理，不截斷、不跳過。已登錄來源的內容或 ID 不得偷偷變更，後續批次也不能省略它們。

## 整合介面

`ImpactGraph.attempt_audit_view(events, question_id=..., question_snapshot_id=...)` 在完整圖上計算傳播，再按題目／快照輸出投影。投影保留原始稽核 ID；建立時已有的模型／工具／污染標記，也保留稽核 ID（有提供時）及不可變來源紀錄引用。投影可傳給 `aggregate.select_inputs`／`build_aggregate` 的 `audit_events`。

投影不是新的人為判讀，不得當作來源 `audit_update` 再寫回稽核事件檔。整合紀錄只保存與實際採用／排除候選及其祖先有關的事件，避免跨題誤歸因。

整合 API 也支援直接指定 attempt 的原始事件（`attempt_id` 或 `target.kind=attempt`）；兩種寫法衝突或題目映射不符時拒絕。子代理等非 attempt 目標必須先經完整圖投影，不能直接傳給整合 API。

離線重播範例（來源內容不輸出到終端機）：

```sh
.venv/bin/python src/audit_ledger.py \
  --records data/forecasts.jsonl \
  --records data/aggregates.jsonl \
  --audits data/audits.jsonl \
  --output data/audit_impacts.jsonl
```

存在子代理／送出來源時，要以額外的 `--records` 一併提供。指定而不存在的檔案會報錯；輸出不得與任何來源路徑、symlink 或 hardlink 指向同一檔案。本輪只在測試暫存目錄執行此 CLI，未讀取實際預測帳冊。
