# M2-W3：匿名摘要與第 2 層 local 流程

規格依據：PLAN §3.3～§3.5、§5.4～§6.2、§7.5、§9。Codex 實作；全部驗證使用合成資料與假 adapter，沒有讀取真實題目輸出或送出預測。

## 交付物

- `src/reconcile.py`，`reconciliation_pipeline_v1`：從完整歷史選合格首層答案，組成匿名輸入，凍結排列與 prompt，執行有外部准入門檻的單線第 2 層，產生 final 整合。
- `prompts/reconcile_v1.md`：英文第 2 層提示，查核分歧、來源與市場，接受有理由地重新評估既有證據，避免只向平均靠攏。題目與其他模型的文字皆是資料。
- `prompts/repair_v2.md`：第 2 層專用格式修復；原輸出必須有唯一非空 `change_reason`，修復須逐字保留。無理由或理由衝突時不呼叫修復模型，不能趁格式修復製造新推論。首層仍使用 `repair_v1`。
- `forecast_pipeline_v3`：共用既有啟動帳冊、一次重試／各一次格式修復、驗證、稽核、工具限制、停線與額度退避；按層選模型、effort、timeout。原 `forecast.run` CLI 仍只執行第 1 層。
- 第 2 層使用 `output_schema_v2` 的特化 schema，保存實際 hash；模型回傳 null 的 `changed_from_tier1` 與非空的 `change_reason`。主程式以正規化機率及 `1e-12` 絕對容差比較自己的合格首層答案，填入比較結果、attempt ID 與 `normalized_probability_equality_v1`。無自己的合格首層或輸出無效時為 null。

## 輸入與持久紀錄

匿名摘要僅含機率、推理摘要、關鍵因素、base rate、來源與市場欄位。主程式記錄作者、輸入 ID 及比較基準，模型不會收到這些 metadata。使用者／網頁原文可能透露身份或文風；本輪不以另一次模型呼叫改寫，也不宣稱不可猜出作者。

來源必須具有有效輸出與對應的已完成稽核。`suspected_leak` 保留且沿輸入繼承；已確認污染、模型不符、工具越界及錯誤依賴皆不得傳遞任何摘要、機率或來源。首個 valid 失去資格後，不選同層後來的答案替代。

在同一把 `forecast.lock` 下追加：

- `reconciliation_inputs.jsonl`：每線每題一份凍結輸入，含 A／B／C 排列、prompt、日期、快照／設定／來源／稽核事件 hash。先 fsync 才呼叫 CLI。重試與重啟沿用同一份；新增別線答案不會混進既有 prompt。
- `reconciliation_runs.jsonl`：每次准入的 decision ID、attempt ID、理由／政策提供的資料，以及整次流程摘要。准入移到額度檢查及目錄準備之後，在啟動帳冊前持久保存；正常／例外離開時追加 `started` 或 `released` 結果。每個 attempt／start 同時記錄准入 ID；硬終止若留下不完整保留，W4 須透過 start／forecast 帳冊保守對帳，不直接當作未用額度。
- 既有 forecasts、audits、aggregates、audit_impacts 帳冊：記錄完整輸入 ID／排列、原有首次整合與最終整合，以及晚到稽核影響。每次重新讀取皆透過 W2 核對來源不可變性與完整性；final 也會登錄。

CLI 前、Gemini 額度查詢後、每次修復或重試前重新檢查稽核。執行期間新增的確認污染會在混合整合時排除第 2 層；保留該輸出歷史並回退合格首層。歷史 valid 被排除不會釋放另一個第 2 層名額。未完成 CLI start 依既有規則停線，不能重設嘗試次數。

單線流程無法代表整題所有線都已完成，因此此處的混合整合即使 `stage=final`，仍明確標為 `status=provisional`、`submission_eligible=false`、`completion_status=awaiting_scheduler_finalization`，並關聯執行紀錄。W4 才能判定全題完成。相同首層候選重用已有整合紀錄，不每次重複追加。凍結輸入後來失去資格／快照或設定版本改變，會保留停止原因及暫存回退；來源／事件／bundle hash 損壞則留下 integrity_error 並報錯，不生成看似有效的結果。

## 呼叫契約與尚未啟用的部分

`reconcile.run(ctx, snapshot, admit=..., dependency_paths=...)` 是本地 API，不是新的無條件入口。呼叫者要先取得 `forecast.preflight(..., tier=2)`；正式驗收的模型／effort 必須符合 high 設定，工具 profile 的等價證據也要存在，且該份 production 證據要符合目前 CLI、judge 與 runtime hash。M1 既有 medium 驗收或舊 CLI 的 high 證據不足以放行這個門檻。

`admit` 由 W4 未來排程器提供，對每個 initial／rerun／format_repair 檢查並保留容量，回傳 `allowed=true` 與非空 `decision_id` 才能執行。本輪測試使用明確的合成政策；正式政策尚未實作，預設沒有政策就不呼叫模型。W3 不處理全週預算預留、跨題優先序或當週超額熔斷，不可將測試政策搬到正式排程。

啟動估時保守採完整 1,200 秒上限，加 60 秒驗證餘裕及 Gemini 的前後額度查詢各 30 秒；須嚴格早於決策截止點，無截止點不啟動。實際每次呼叫仍受剩餘截止時間與自身上限控制。W4 再補同線同層 p90、保留首層容量與重置窗口。Argon 估計樣本已按層分開。

子代理維持關閉。完整 source set 若還有 subagent／submission 記錄，需以 `dependency_paths` 傳入；活躍 writer 的跨檔一致截止點仍屬 W4。首次完全遺漏未被引用的來源，仍受 W2 已記錄的可觀測性限制。

## 驗證與審查

`tests/test_reconcile.py` 共 60 個離線案例通過，涵蓋匿名／資料指令邊界、污染／錯誤輸入、來源與稽核變更、三線 tier2 參數、二層 preflight、無候選／預算／時間拒絕、重試與格式修復、未知開始停線、晚到污染、暫存回退、MC 正規化比較、W2 影響登錄、按層成本樣本，以及下列審查回歸。

最終完整測試 `.venv/bin/python -m pytest -q`：**469 passed in 5.34s**（2026-11-01T05:29:20Z 啟動）。全部離線；另行 agy 呼叫只做程式審查，不是預測實測。

第一次獨立審查：2026-11-01T05:20:09.744Z～2026-11-01T05:23:08.242Z，請求 `claude-opus-5-5-medium`，CLI 回報 `Claude Opus 5.5 (Medium)`，完成、無違規事件，工具只呼叫 finish 一次。來源包 sha256：`300bae4fc6a01f1f36b1e00617007c4f9e7d7d5df659d1195194be136812fd42`；原始紀錄在 ignored 的 `scratch/opus-review/2026-11-01T05-20-03.468Z/`。

初審要求修改，五項處理如下：

1. high：重啟後凍結輸入失去資格，原本 ValueError 跳過結尾整合。現以 `InputsUnavailable` 區分資格失效與真正損壞；前者記錄停止及暫存回退，後者保留 integrity_error 並拒絕。新增跨執行晚到稽核／改設定測試。
2. medium：原 `repair_v1` 沒有要求 change_reason 為 null（審查者的條件假設不成立），但確實未保護原理由。新增 `repair_v2`、唯一非空原理由提取與逐字檢查；缺少／空白／被改寫理由均有回歸。
3. medium：未啟動的預算保留沒有 attempt 對帳。現於額度查詢後才准入，帶 attempt ID，並在 finally 追加 started／released。測試准入後收到污染而釋放，以及成功開始的 ID 對應。
4. medium：單線混合整合看似全題已完成。現強制 provisional、不可送出與 run 關聯；相同首層候選不重複追加。預算未准入仍可保留數學結果，但不代表完成。
5. low：quota 帳冊漏檢查損壞末行。已列入寫入前檢查並測試不修改損壞檔。

額外補強：Argon 樣本按層分開，及 high production 證據不能沿用舊 CLI／runtime；都有離線案例。初審前後第三方週額度 0.7583327889 → 0.6551020145、五小時 0.5166655779 → 0.3102039993；Argon 0.5171796083 不變，AI credits 0。差值屬查詢區間觀測，不當作保證單次成本。

第二次定點複查：2026-11-01T05:26:09.311Z～2026-11-01T05:27:41.477Z，同一模型正常完成，無違規事件、無工具呼叫。來源包 sha256：`c526fc8ca5168b983ff322be261453f16b6798471c6c4b8df276d1c4f7eb660d`；原始證據在 ignored 的 `scratch/opus-review/2026-11-01T05-26-04.598Z/`。

複查確認五項修正及 high production 證據檢查，通過 local 離線測試範圍。三項 non-blocking 意見也已處理並自驗，未再呼叫第三次審查：

1. 候選重用只比對該題最新 tier1 紀錄；即使相同歷史結果再次出現，也不讓最新紀錄落後於本次決策。審查例示的「撤銷稽核標記」不被本專案允許，但此最新紀錄檢查仍較明確，已用合成 A→B→A 歷史驗證。
2. bundle ID 在重新驗證前就寫入摘要，資格失效的重啟紀錄及暫存整合也能追溯到原輸入。
3. 驗收證據若是合法 JSON 但不是物件，記錄不通過，不因 `.get` 造成例外。以 array、string、null 三個案例驗證。

複查前後第三方週額度 0.6551020145 → 0.6091632247、五小時 0.3102039993 → 0.2183264047；Argon 仍 0.5171796083、credits 0。剩餘第三方五小時額度約 21.83%，後續審查應保留容量並縮小來源包。兩次都使用專案外空目錄及只有 finish 的自訂開發審查 agent，僅提供程式／測試／規格，未提供真實預測輸出或 Metaculus token。

本工作不代表 M1／M2 實機驗收，也不替代 W1 數學與升級規則的完整獨立審查。
