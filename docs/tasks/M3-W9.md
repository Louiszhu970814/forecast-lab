## 需求

### 1. `trial` 不得送到任何比賽的題目（D79、硬性規則 2）

- 一個 post 可以同時屬於多個 project。例如 Metaculus Cup 的題目常常同時掛在主站。
- `trial` 下，只有在題目**不屬於任何比賽（tournament 類型的 project）**時才可以送出；bot testing area 本身除外。判斷依據是官方 API 回傳的 post 歸屬（`projects` 欄位的各類 project），不是題目標題、也不是本地快照的單一 `tournament_id`。
- 歸屬資料缺漏、格式不認得，或無法確定 project 類型時，一律拒絕（暫時性，可重試），不得當成安全。
- 同時套用在三個地方：`continuous.Poller` 選題、`m2_prepare.py` 選題、`submit.py` 送出前的檢查。送出前要用剛取得的 post 重新判斷，不能只信任輪詢時的結果。
- 測試至少涵蓋：同時屬於 Cup 的主站題目、同時屬於 Market Pulse 的主站題目、只屬於主站的題目、bot testing area 的題目、歸屬欄位缺漏、不認得的 project 類型。

### 2. MiniBench 系列白名單（`live`，D77）

- `config/tournaments.json` 的 `minibench` 條目維持 `"id": null`。系列是否核准，看該條目的 `submit_whitelisted`。本任務**不修改**設定檔，測試用測試自己的設定。
- `live` 下，題目的 `tournament_id` 必須是官方 API（`projects/minibenches/` 與 `minibench` 別名）此刻列為 ongoing 的某一輪，而且 `minibench.submit_whitelisted` 為真，才可以送出。每次送出都記錄實際的輪次 ID。
- 主賽仍然只用靜態 ID 與 `submit_whitelisted`。`live` 的其他行為不放寬：未核准的系列、已結束或尚未開始的輪次、發現失敗或結果不一致，一律拒絕。
- `continuous.Poller` 在 `live` 下要能輪詢所有 ongoing 的 MiniBench 輪次（同時有兩輪也要涵蓋），不能因為 `minibench.id` 是 `null` 就報錯。
- 測試至少涵蓋：兩輪同時 ongoing、輪次切換、upcoming 的輪次被拒絕、系列未核准、發現失敗、題目屬於主賽。

### 3. 真實的 Transport（V15 介面）

新增一個以官方 API 實作 `submit.Transport` 的類別。`src/metaculus.py` 只做讀取、維持唯讀；寫入的程式放在 `submit.py` 或新的模組。

- **身分**：`account()` 讀 `users/me/`，回傳 id 與 `is_bot`。`submit.py` 現有的「帳號必須等於核准的機器人 ID」檢查照舊。
- **讀取**：`get_post()`、`current_tournaments()`、`tournament_index()` 沿用既有的唯讀客戶端與 `continuous.current_tournaments()`。
- **寫入**：`write()` 以 POST 呼叫 `/api/questions/forecast/` 與 `/api/comments/create/`（payload 格式沿用 `submit.py` 現有的組裝函式）。
  - 只允許 HTTPS，主機必須是 API 主機，不跟隨任何轉址。
  - token 只放在 `Authorization` 標頭，不出現在紀錄、例外訊息或任何輸出中。
  - POST **不自動重試**：逾時、連線中斷、5xx、無法解析的回應，一律交給現有的狀態機記為結果未知（`unknown`），再由讀回對帳決定。
  - 4xx 回應保留狀態碼與經過清理的錯誤摘要，不得包含 token。
- **讀回**：`readback()` 依 `Transport` 文件的契約實作。
  - 預測：讀 post 的 `question.my_forecasts`，只有在找到「晚於這個請求開始時間、且機率與送出的 payload 一致」的預測時才回傳 `found`。
  - 留言：讀該 post 中本帳號的留言，只有在找到「晚於請求開始時間、且內容 hash 一致」的留言時才回傳 `found`。
  - 其餘情況一律是 `unknown`。`not_accepted` 只能在有權威證據時使用；沒有這種證據就不要回傳。
  - 讀回所用的欄位名稱與查詢參數都是 V15 的假設：集中寫成常數，並在執行回報列出每一個假設，方便 Claude 實測時逐項確認。
- **接上 CLI**：`submit.py run` 在模式為 `trial` 或 `live` 時使用真實 Transport；`local` 維持現在的 dry-run 行為，不建立任何網路寫入物件。
- **測試**：全部用假的 HTTP opener，不連網。至少涵蓋：轉址被拒、非 API 主機被拒、POST 不重試、逾時記為未知、4xx 摘要不含 token、讀回找到／找不到／欄位缺漏、`local` 模式不建立寫入物件，以及 token 不出現在任何紀錄中（掃描測試產生的所有帳冊與 stdout／stderr）。

| 用途 | 待實測假設 |
|---|---|
