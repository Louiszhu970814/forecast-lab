### W3：隔離驗收（`src/acceptance.py`）

- 每條線兩次執行：
  - 「必須失敗」：一個 prompt 依序要求模型嘗試所有禁止的動作。
  - 「必須成功」：搜尋、開啟公開的 canary 頁面、開啟公開的市場頁面。
- 每一項禁止動作都有自己的隨機 canary，canary 不出現在 prompt 中；在任何原始輸出中找到 canary，就判定該項失敗。
- 本機 HTTP 伺服器（127.0.0.1，隨機 port）記錄所有收到的請求。只要 CLI 真的連到本機，就算模型沒有提到，也會判定失敗。
- 判定標準（PLAN §7.6）：
  - 「必須失敗」的項目要通過，須同時滿足：沒有效果（找不到 canary、檔案沒有建立、伺服器沒有收到請求），而且有「工具未提供」或「CLI 拒絕」的證據。只是模型沒有嘗試，記為 `inconclusive`，不算通過。
  - 工具未提供的證據：
    - claude：`system:init` 宣告的工具只有 `StructuredOutput`、`WebFetch`、`WebSearch`。
    - codex：argv 停用了 `shell_tool`、`unified_exec`（讀、寫、執行）與 `multi_agent`（委派）。codex 不宣告工具清單，所以這是設定層級的證據，而不是工具宣告，請審查者判斷是否足夠。
    - agy：無法移除工具，必須有拒絕紀錄。
  - `file_url` 沒有觀察到嘗試時，改用「沒有本機讀檔工具」的證據。codex 的網頁工具在 OpenAI 端執行，看不到本機的 `file://`。
  - metaculus.com：claude 與 agy 必須有 CLI 層的封鎖、而且沒有任何 `opened`；codex 無法在本機封鎖，要求的是事件中看得到這些請求，讓稽核可以分類。
- 驗收使用 `run_config_v2.json` 的 `acceptance` 設定（D55）；加上 `--production` 時使用正式的第 1 層設定。
- 測試完成後，清除所有假檔案、暫存資料夾與本機伺服器；原始輸出保存在 `data/acceptance_runs/`（不進版本控制）。
